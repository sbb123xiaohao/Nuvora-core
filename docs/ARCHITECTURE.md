# 架构与工程边界

## 启动与代码组织

`arch/i386` 和 `arch/x86_64` 分别提供启动入口、中断保存/恢复和 GDT 加载。共享内核位于 `kernel/`；`arch.c`/`arch64.c`、`memory.c`/`memory64.c` 根据编译架构选择实现。`user/` 生成独立 ELF 应用，由 `scripts/mkarchive.py` 嵌入只读应用归档。

内核从 1 MiB 物理地址链接。Multiboot v1 进入 32 位入口。i686 直接建立运行环境；x64 检查长模式与 NX 能力，建立临时大页映射，启用 PAE 与 EFER.LME/NXE，再远跳转进入 64 位代码。C 初始化阶段替换为正式的 4 KiB 页表。

x64 的可调试内核是 ELF64。为适配只接受 ELF32 的 Multiboot 加载器，`objcopy` 另外生成 ELF32 启动容器，装载地址和已链接机器码保持不变。测试同时验证容器启动、ELF64 用户程序和高 32 位寄存器保存，因此 x64 支持不依赖 32 位兼容执行模式。

## 内存

| 区域 | 范围 / 上限 |
| --- | --- |
| 物理管理范围 | 0–128 MiB，按启动器的可用内存表分配 |
| 内核链接基址 | `0x00100000` |
| 内核堆 | 静态保留 8 MiB，16 字节对齐，空闲块合并 |
| 用户 ELF 映像窗口 | `0x40000000`–`0x41000000` |
| 用户堆 | `0x50000000`–`0x50400000` |
| 用户栈 | 栈顶 `0x7fff0000`，向下映射 8 页 |
| 用户栈保护 | 栈下方页面不映射 |
| 每进程内核栈 | 16 KiB，位于 `0x10000000` 起的共享 supervisor 区域；上下各有 4 KiB 不映射保护页 |

物理分配器初始标记所有页不可用，再开放内存表中的可用页；保留区覆盖可用区，最后保留低地址、内核和启动模块。分配页清零，使用独立分配位图区分已分配页与保留页，归还保留页或重复归还触发诊断。位图搜索从上次位置继续，避免每次从零扫描。页表与内核栈分配失败会回滚本次分配；用户堆失败不改变 break。

i686 使用两级页表。x64 使用 PML4 → PDPT → PD → PT 四级表：PDPT 槽 0 是共享的 supervisor 内核映射，槽 1 是进程私有用户映射。这里保留了较小的地址窗口，**尚未实现 4 GiB 以上物理内存和完整 64 位用户地址空间**。

两种架构均设置 CR0.WP，并以页权限隔离用户和内核。x64 将数据、用户堆和用户栈设为 NX，代码页只读且可执行；i686 没有 PAE/NX，不能阻止从可写数据页执行。ELF 加载器拒绝同时声明写和执行的段，但这在 i686 上不等于硬件 NX。

## 进程与中断

固定 32 个进程槽。PIT 100 Hz，默认每 5 tick 进行一次轮转选择。时钟在用户态中断时保存上下文并可切换进程；系统调用和其他内核代码执行时关闭可屏蔽中断，不实现内核抢占。

运行状态包括 ready、sleep、wait 和 zombie。等待只能领取子进程状态一次。退出时关闭句柄，唤醒等待者，孤儿进程转为无父进程；页表与内核栈在进入其他进程的系统调用或调度器后回收，避免释放当前栈。未被 WAIT 领取的 zombie 只保留 PID、父进程和退出状态等元数据，不再占用用户内存和内核栈；状态被领取或进程成为孤儿后释放进程槽。

x64 保存全部通用寄存器，使用 TSS.RSP0 切换用户/内核栈，并为双重故障设置独立 IST 栈。i686 的双重故障通过专用 TSS 和 task gate 切换到独立 8 KiB 应急栈。x64 的其他中断不使用 IST。FPU、MMX、SSE、AVX 上下文尚未实现，CPU 的相关执行条件被关闭，避免静默共享浮点寄存器状态。

普通用户异常终止对应进程，退出状态为 `128 + 异常向量`。内核态异常进入 panic。初始进程 PID 1 被保护，不能由 `quench` 终止；PID 1 主动退出或异常时给出明确的停止诊断，不再无限等待。系统没有 init 自动重启机制。


## USB 控制器与外设

`kernel/usb.c` 在 PCI 配置空间中扫描 USB 控制器，识别 UHCI、OHCI、EHCI 和 xHCI。当前驱动只启动 xHCI：映射控制器 MMIO，建立 DCBAA、命令环、事件环和每个设备的控制/中断传输环，使用 Enable Slot、Address Device、Evaluate Context、Configure Endpoint 和 Disable Slot 完成生命周期。所有 DMA 页来自内核物理分配器，位于本版可管理的低地址物理范围；x64 和 i686 共享同一 USB ABI。

设备枚举读取 Device、Configuration、Interface、Endpoint 和字符串描述符，保留 VID/PID、USB 版本、速度、类别、序列号以及 Hub 父端口。Hub 使用标准端口状态和变化请求递归扫描，`ports --scan` 可立即触发扫描，后台也会周期处理热插拔。USB HID Boot Protocol 键盘配置一个 8 字节中断 IN 端点，支持修饰键、功能键、导航键、Caps Lock 和自动重复，并将事件送入 Loom/Folio。鼠标、U 盘和其他接口只做描述符识别；没有 USB 大容量存储块层、文件系统挂载或鼠标光标。

USB 设备接口通过 `NV_USB` 系统调用提供有界的控制器和设备结构查询。输出指针写入前检查完整用户可写范围；xHCI 错误会停止控制器并隔离 DMA 页，设备拔除先完成 Disable Slot，再回收设备资源。非 xHCI 控制器会显示 `unsupported`，不伪造运行状态。

## ELF 与 ABI

各架构只接受自身的静态 ET_EXEC 格式：i686 为 ELF32 / EM_386，x64 为 ELF64 / EM_X86_64。检查 ELF 类别、端序、程序头范围、段大小、加载地址、对齐、入口和页重叠；不支持动态链接、TLS 或另一架构的兼容应用。失败加载回收已分配资源。`EXEC` 在独立临时地址空间中完成相同的 ELF 检查、用户栈映射和参数复制，全部成功才切换 CR3 并回收旧映像。它保留 PID、父子关系、当前目录、累计 CPU tick 与打开的句柄/偏移；重置用户堆、用户栈和寄存器，释放原程序的屏幕租约。失败时原地址空间、句柄和屏幕租约不变。

系统调用使用 `int 0x81`，详见 [ABI.md](ABI.md)。每次复制用户缓冲区之前检查完整页范围和权限；字符串逐页检查并受长度上限约束。此版本没有异步设备 DMA，因此不存在驱动在返回后继续访问用户指针的接口。

## 文件与设备

文件系统以 128 个 vnode 组成的树实现。节点类型分发到 RAM 文件、设备或动态状态视图。没有通用 mount 接口、块缓存、inode 日志、符号链接或 ACL；`ramfs/devfs/proc` 描述这里的行为，不代表实现了 Linux 的完整对应子系统。

文件描述符 0/1/2 为控制台；3–15 为每进程独立句柄。普通文件最多 128 KiB，写入按需扩展缓冲区，稀疏区清零。排他创建在一次系统调用内完成，创建前检查拼接后的规范绝对路径长度，避免相对路径层层进入后产生无法表示的节点。移动检查目录环和路径长度，目标存在时失败；普通文件的目标路径不能以 `/` 结尾。删除检查引用计数、当前目录和非空目录。

串口为 COM1，键盘输入支持 PS/2 set 1 和 xHCI USB Boot Protocol；显示为 80×25 VGA 文本。状态视图在读取时生成，并非跨多次读取的一致快照。控制台输入为非阻塞轮询；Loom 在没有输入时休眠。

## 磁盘快照

仅支持传统 IDE primary master、512 字节扇区、LBA28 PIO。只有扇区 0 的专用签名、版本、几何参数和 CRC 全部符合时才允许写入；驱动的写入范围进一步限于两个快照槽。脚本只创建新普通文件，不格式化现有文件或宿主块设备。

专用数据镜像为 8 MiB。槽 A 从 LBA 8 开始，槽 B 从 LBA 4096 开始，每槽 1 个头扇区和最多 2048 个数据扇区。记录使用小端固定字段，包含完整 `/home/...` 路径和数据，按父目录优先的顺序导出。

一次 `anchor`：序列化并确认容量 → 清空备用槽头并 flush → 写数据并 flush → 写带校验的提交头并 flush。成功后更新内存中的当前代次。旧槽保留。启动先尝试较新的完整快照，校验或导入失败则尝试旧槽；CRC 是损坏检测，不提供防伪认证。

恢复只发生在启动期。导入检查字节范围与规范路径；若实际构建目录树失败，清理本次导入后尝试旧槽。测试覆盖校验损坏、非法路径、越界长度、部分头部损坏与重启恢复。**没有验证所有物理磁盘断电和写缓存语义。** PIO 使用忙等超时，没有错误重置、DMA、AHCI 或高级掉电保护。

## 安全与可靠性范围

本版可验证基本 Ring 3 隔离，但不承诺能承受任意敌对二进制、侧信道攻击或长期生产负载。缺少多用户权限、资源配额、信号、可靠 I/O 恢复以及生产级调度与内存压力处理。一个进程可以消耗共享文件节点或填满用户进程槽，触发返回错误；PID 1 负责管理。

长时间关闭中断的磁盘 I/O 会影响 PIT tick 计时精度。因此 `tempo` 和 `horizon` 的时间是处理到的 tick，不是经校准的墙上时钟。

## Folio 文档层

Folio 是一个运行在 Ring 3 的全屏用户态程序。内核提供独占屏幕租约、80×25 字符表面提交和带修饰键的 PS/2/串口键盘事件；程序退出或异常时内核恢复 Loom 的终端画面。表面提交一次校验完整用户缓冲区，不能写入 VGA 之外的地址。

编辑器在用户空间维护最多 32 KiB 的字符数组，每个字符带有粗体、斜体、下划线和段落属性。段落属性包含正文、两级标题、引用、四种对齐、项目符号、单/双倍行距和段前分页。布局器按 64 列、48 行正文页生成预览，RTF 写出时使用 11906×16838 twips 的页面、1 英寸边距、Courier New、标题字号和页脚页码。

`.nvd` 是 Nuvora 的小端格式：`NVFOLIO1`、字符数、CRC32 和每个字符的 3 字节记录。纯文本打开时将 CRLF 规范化为 LF；不接受控制字符或非 ASCII 字节。保存使用同目录临时文件和 `REPLACE` 系统调用，目标已打开时拒绝替换；失败时保留原文件。文档格式不写入普通 `.txt`/`.md`，避免把二进制元数据混入纯文本。
