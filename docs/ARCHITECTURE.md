# 架构与工程边界

## 启动与代码组织

`arch/x86_64` 提供 PC 启动和中断入口，`kernel/` 提供 x64 内核，`user/` 生成独立 ELF 应用并嵌入归档。`arch/aarch64` 提供 QEMU virt 上的 Image、设备树、页分配、EL1 页表与单个 EL0/NEON 程序。i686 构建和启动源码已移除；两种 64 位架构的当前功能范围见 [ARM64-AI.md](ARM64-AI.md)。

x64 内核从 1 MiB 物理地址链接；其 BIOS 与 UEFI 路径最终进入 `kernel_start`。Multiboot v1 先进入 32 位汇编入口，检查 CPU 能力；x64 建立临时映射、启用长模式后在 C 中转换有界的启动信息。x64 UEFI 路径已有固件建立的长模式环境：stub 校验完整 ELF 和固件内存所有权，记录 EFI 内存图、GOP 与 RSDP，每次 `ExitBootServices` 重试都重新转换内存图；退出成功后切到 stub 自有栈，完成需要延后的段复制，再通过 `uefi_entry` 切到内核自有栈。`kernel_uefi_main` 在更换页表前复制 `boot_info`，后续不再依赖固件栈或原移交对象的映射。两条路径均检查必要 CPU 特性；x64 包括 FPU、CMOV、MSR、PAE、FXSR、SSE/SSE2、长模式与 NX。C 初始化阶段建立正式页表。

x64 的可调试内核是 ELF64。为适配只接受 ELF32 的 Multiboot 加载器，`objcopy` 另外生成 ELF32 启动容器，装载地址和已链接机器码保持不变。测试同时验证容器启动、ELF64 用户程序和高 32 位寄存器保存，因此 x64 支持不依赖 32 位兼容执行模式。UEFI 路径由 `scripts/mkuefi.py` 把以 `--emit-relocs` 链接的 stub ELF 转成 PE32+（`BOOTX64.EFI`，首选基址 0x02000000，携带由绝对重定位合成的基址重定位表），内核 ELF 放在 ESP 的 `\EFI\NUVORA\NUVORA.ELF`；若固件在启动介质句柄上没有暴露文件系统，stub 会枚举所有 SimpleFileSystem 卷再试。

## 内存

| 区域 | 范围 / 上限 |
| --- | --- |
| 物理管理范围 | x64 最高 64 GiB；ARM64 自 0x40000000 起最高 64 GiB，按各自启动内存图分配 |
| 内核链接基址 | x64 `0x00100000`；ARM64 `0x40080000` |
| x64 内核堆 | 8 MiB，在虚拟地址 1 TiB 映射 2048 个可分散的物理页；16 字节对齐，较大对象空闲块合并；小对象由 slab 分配 |
| 帧缓冲窗口 | PML4 槽 3（虚拟基址 1.5 TiB），最多 64 MiB supervisor 映射，只映射 GOP 实际有效页面；物理帧缓冲仍保留在分配器外 |
| 用户 ELF 映像窗口 | `0x40000000`–`0x41000000` |
| x64 用户堆 | `0x50000000`–`0x70000000`（512 MiB） |
| 用户栈 | 栈顶 `0x7fff0000`，向下映射 8 页 |
| 用户栈保护 | 栈下方页面不映射 |
| 每进程内核栈 | 16 KiB，位于 `0x10000000` 起的共享 supervisor 区域；上下各有 4 KiB 不映射保护页 |

物理分配器初始标记所有页不可用，再开放内存表中的可用页；保留区覆盖可用区，最后保留低地址、内核与启动数据。页地址为 `uptr` 宽度（x64 为 64 位），分配页清零，使用独立分配位图区分已分配页与保留页，归还保留页或重复归还触发诊断。x64 与 ARM64 共用 2^order 分阶空闲索引（order 0–18），以忙闲位图作第 0 阶并从两个子块派生较高阶；释放后重新合并，索引按受管页数占用少于 1 bit/页。x64 首选 4 GiB 以上 RAM，`page_alloc_below(4 GiB)` 为 xHCI 等设备保留 DMA 可用页；`page_alloc_run(n)` 分配物理连续且清零的 n 页，非整幂请求仍从位图扫描。小对象按 16–2048 字节分级进入 slab，整页空闲即归还；较大对象沿用可合并的内核虚拟堆。页表与内核栈分配失败会回滚本次分配；用户堆失败不改变 break。内存耗尽自检以 4 个 donor 页构造预算状态，结束时按所有权位图统一归还，额外记录空间不随被管理的 RAM 扩张；耗尽测试的遍历和清零工作量仍随实际可用 RAM 增长。详细边界见 [MEMORY-0.9.0.md](MEMORY-0.9.0.md)。

x64 使用 PML4 → PDPT → PD → PT 四级表：内核主映射的 PDPT 槽 0 覆盖低 1 GiB，槽 1–63 使用 2 MiB 大页覆盖更高物理地址，低 32 MiB 用 4 KiB 页保护内核代码与数据。每个用户空间的 PDPT 槽 1 被私有的 1–2 GiB 用户映射替换，因此另在 PML4 槽 1（虚拟基址 512 GiB）共享 supervisor 物理映射。内核通过 `phys_ptr` 访问所有已分配物理页时统一使用该别名，低于 1 GiB 的页也相同，确保连续缓冲跨越用户地址边界时仍然连续；写 CR3 或释放页时用 `ptr_phys` 转回物理地址，不能直接把别名交给设备 DMA。内核栈与 MMIO 窗口替换了恒等映射，分别覆盖的完整 2 MiB 物理区被保留，避免分配到已无对应 RAM 映射的页。页分配和页表地址仍使用 4 KiB 粒度，提取地址时屏蔽 NX 等标志。**物理管理上限仍为 64 GiB，用户地址空间仍为 1–2 GiB**。

x64 内核堆单独使用 PML4 槽 2（虚拟基址 1 TiB），与物理别名分离。`vm_heap_create` 逐页取得 2048 页；全部成功后才发布页表并通过 `page_pin` 永久保留。任何中途失败都会清除临时叶表并归还全部已取页面；进程页表共享该 supervisor/NX 映射，进程销毁只回收私有页面。内核堆不再要求连续物理内存，`ptr_phys` 也不能用于把堆对象当作连续 DMA 缓冲。

PML4 槽 3 映射固件提供的像素帧缓冲，不再从低端物理 RAM 挖掉 8 MiB 虚拟窗口。用户程序只能经 `NV_SUB_DISPLAY` 查询并按矩形复制像素，无法映射显存；一个进程独占显示租约。桌面工作流及应用 SDK 见 [SDK.md](SDK.md)。

PCIe NVMe 数据盘使用 4 GiB 以下的专用 DMA 页、一个管理队列和一个轮询
I/O 队列；IDE 主盘的有效 Nuvora 卷优先，均通过相同 GPT 和快照边界检查。
xHCI Boot 鼠标的相对事件经过仅供像素屏持有者消费的 `NV_SUB_INPUT` 队列。
HDA 音频输出的 codec 动词和流描述符由内核驱动处理，`NV_SUB_AUDIO`
只复制定长 PCM 到内核私有 DMA 页；同步等待传输时允许 PIT/键盘中断。
设备条件和未支持的硬件类型见 [DEVICES.md](DEVICES.md)。

x64 设置 CR0.WP，并以页权限隔离用户和内核：数据、用户堆和用户栈设为 NX，代码页只读且可执行，ELF 加载器拒绝同时声明写和执行的段。ARM64 将内核代码标为 RO、内核数据和用户数据标为 NX，并验证 EL0 不能读取 supervisor 代码页。

## 进程与中断

固定 32 个进程槽。PIT 100 Hz，默认每 5 tick 进行一次轮转选择。时钟在用户态中断时保存上下文并可切换进程；系统调用默认关闭可屏蔽中断，音频传输等待期间暂时开放中断以保持 PIT/键盘响应。内核态中断不调度其他进程，不实现内核抢占。

运行状态包括 ready、sleep、wait 和 zombie。等待只能领取子进程状态一次。退出时关闭句柄，唤醒等待者，孤儿进程转为无父进程；页表与内核栈在进入其他进程的系统调用或调度器后回收，避免释放当前栈。未被 WAIT 领取的 zombie 只保留 PID、父进程和退出状态等元数据，不再占用用户内存和内核栈；状态被领取或进程成为孤儿后释放进程槽。

x64 保存全部通用寄存器，使用 TSS.RSP0 切换用户/内核栈，并为双重故障设置独立 IST 栈。x64 的其他中断不使用 IST。`kernel/cpu.c` 管理每进程对齐的 512 字节浮点状态区；FXSAVE/FXRSTOR 保存 x87、MMX 和 SSE。每次调度立即保存与恢复，成功 EXEC 重置状态。AVX/XSAVE 仍关闭。内核 C 继续禁止生成浮点/SIMD 指令，详见 [CPU-GPU.md](CPU-GPU.md)。

普通用户异常终止对应进程，退出状态为 `128 + 异常向量`。内核态异常进入 panic。初始进程 PID 1 被保护，不能由 `quench` 终止；PID 1 主动退出或异常时给出明确的停止诊断，不再无限等待。系统没有 init 自动重启机制。

## ACPI 与 PCIe 配置空间

`common/acpi.c` 通过物理读取回调实现可单独测试的早期 ACPI 解析。它先查 EBDA 的前 1 KiB，再按 16 字节边界查 `0xe0000`–`0xfffff`；RSDP 1.0 校验前 20 字节，2.0 以上还校验声明长度与扩展校验和。XSDT 无效时可回退到有效 RSDT。根表和 MCFG 都检查签名、最小/最大长度、记录整除、完整校验和、地址溢出、1 MiB 对齐、总线范围和同 segment 重叠；记录数固定上限为 8。

`kernel/acpi.c` 使用 MMIO 区最后一页作为临时 supervisor-only、不可缓存映射，逐页读取低端 BDA、BIOS ROM 或更高物理地址，不把固件地址直接当作已映射指针。其余 511 页仍供 xHCI 和设备 BAR 的持久映射使用。x64 另按 CPUID 物理地址宽度检查。

`kernel/pci.c` 只启用 segment 0 的 MCFG 区域，并先比较范围起始 BDF 的 ECAM 与 CF8/CFC 读取结果。覆盖范围内每个 function 可访问 4096 字节配置空间；未覆盖总线、没有 MCFG、项目被拒绝或启动参数为 `nv.no-ecam=1` 时使用传统 256 字节 CF8/CFC。ECAM 同样复用单页临时窗口，访问期间关闭中断，符合当前单 CPU 模型。尚未实现多 segment、AML `_CRS`/`_CBA`、PCI 资源重新分配、热插拔、MSI/MSI-X 启用或 IOMMU。

接口、启动选项和验证边界详见 [ACPI-PCIE.md](ACPI-PCIE.md)。


## USB 控制器与外设

`kernel/usb.c` 通过共享的 `kernel/pci.c` 枚举 USB 控制器，识别 UHCI、OHCI、EHCI 和 xHCI。当前驱动只启动 xHCI：映射控制器 MMIO，建立 DCBAA、命令环、事件环和每个设备的控制/中断传输环，使用 Enable Slot、Address Device、Evaluate Context、Configure Endpoint 和 Disable Slot 完成生命周期。所有 DMA 页来自内核物理分配器，位于本版可管理的低地址物理范围；ARM64 尚无 USB 驱动。

设备枚举读取 Device、Configuration、Interface、Endpoint 和字符串描述符，保留 VID/PID、USB 版本、速度、类别、序列号以及 Hub 父端口。Hub 使用标准端口状态和变化请求递归扫描，`ports --scan` 可立即触发扫描，后台也会周期处理热插拔。USB HID Boot Protocol 键盘配置一个 8 字节中断 IN 端点，支持修饰键、功能键、导航键、Caps Lock 和自动重复，并将事件送入 Loom/Folio。鼠标、U 盘和其他接口只做描述符识别；没有 USB 大容量存储块层、文件系统挂载或鼠标光标。

USB 设备接口通过 `NV_USB` 系统调用提供有界的控制器和设备结构查询。输出指针写入前检查完整用户可写范围；xHCI 错误会停止控制器并隔离 DMA 页，设备拔除先完成 Disable Slot，再回收设备资源。非 xHCI 控制器会显示 `unsupported`，不伪造运行状态。

## 显卡发现

`kernel/gpu.c` 使用同一 PCI 枚举服务，以 class 03 查找显示设备，按 vendor 0x10de 标记 NVIDIA。只读解析器 `common/pci_decode.c` 处理 32/64 位 BAR、subsystem ID、IRQ、有界的 MSI/MSI-X/PCIe legacy capabilities 链，以及 ECAM 可用时的 AER、ACS、ATS、SR-IOV、Resizable BAR、PASID 和 DPC 扩展链。错误偏移、环和超过 64 项的链会停止并标记；不写 GPU 配置或寄存器、不加载固件。`NV_HARDWARE` 向用户态提供固定布局的 CPU、显卡与平台快照。详见 [CPU-GPU.md](CPU-GPU.md)。

## 设备控制扩展

0.5.1 整合 `NV_DEVCTL` 通用分发和 `cpu_ioctl` / `gpu_ioctl`。GPU MAP_BAR 先验证完整 16 字节读写缓冲区，再准备首个对齐页面的 supervisor 映射；每个 BAR 缓存一份，跨进程复用，失败响应清零。映射大小不等于真实 BAR 大小，没有 GPU 寄存器访问或用户态 GPU 读写。CPU 控制和 GPU 模式/提交接口尚未实现；当前开发版增加小范围实体网络支持，详见 [DEVCTL.md](DEVCTL.md) 和 [NETWORK.md](NETWORK.md)。

## ELF 与 ABI

x64 只接受 ELF64 / EM_X86_64 静态 ET_EXEC；ARM64 尚无 ELF 装载。检查 ELF 类别、端序、程序头范围、段大小、加载地址、对齐、入口和页重叠；不支持动态链接、TLS 或另一架构的兼容应用。失败加载回收已分配资源。`EXEC` 在独立临时地址空间中完成相同的 ELF 检查、用户栈映射和参数复制，全部成功才切换 CR3 并回收旧映像。它保留 PID、父子关系、当前目录、累计 CPU tick 与打开的句柄/偏移；重置用户堆、用户栈和寄存器，释放原程序的屏幕租约。失败时原地址空间、句柄和屏幕租约不变。

系统调用使用 `int 0x81`，详见 [ABI.md](ABI.md)。每次复制用户缓冲区之前检查完整页范围和权限；字符串逐页检查并受长度上限约束。USB DMA 仅使用驱动自有内核页，没有驱动在返回后继续通过 DMA 访问用户缓冲区的接口。

## 文件与设备

文件系统以 512 个 vnode 组成树。NVSTORE3 普通文件用 64 位长度、偏移和
4 KiB 连续块区间，空洞读零，数据分块直读写磁盘。覆盖写先分配新块，
分配/I/O 失败保留旧映射；两个已提交元数据根和当前工作树引用的块都被保护。
NVSTORE1/2 旧盘及无盘/临时目录继续使用 64 MiB 的页式文件路径。

描述符 0/1/2 为控制台，3–15 为普通句柄。新增 SEEK64/STAT64/LIST64；
旧 SEEK 对超出正 int 范围的位置返回 E2BIG，不回绕。排他创建、引用计数、
目录环与路径边界检查保留；跨持久卷和临时卷的 rename/replace 均拒绝。
无通用 mount、块缓存、符号链接或 ACL；设备/proc 是有限的专用节点分发。

串口为 COM1，键盘输入支持 PS/2 set 1 和 xHCI USB Boot Protocol；文本控制台为 80×25——BIOS 启动走 VGA 文本内存，UEFI 启动走 GOP 线性帧缓冲加内置 5×7 点阵字体（PML4 槽 3 独立的最多 64 MiB supervisor 窗口，覆盖的物理 RAM 从分配器保留），两条路径渲染同一份单元缓冲。UEFI 上的 `NV_SUB_DISPLAY` 支持应用独占屏幕并提交像素矩形，旧字符屏与之互斥。状态视图在读取时生成，并非跨多次读取的一致快照。控制台输入为非阻塞轮询；Loom 在没有输入时休眠。

## 磁盘快照

GPT 分区扩展：对 IDE primary master 的 protective MBR、主/备 GPT 头、分区
数组 CRC、LBA 范围与分区重叠进行有界扫描。已格式化的 Nuvora 分区按顺序
成为 C: 至 F:，各自有独立双槽快照；其他格式只显示不写入。无 GPT 的
旧整盘 NVSTORE 镜像继续作为 C:。路径映射和容量限制见 [PARTITIONS.md](PARTITIONS.md)。

磁盘由 IDE primary master PIO/LBA48（必要时 LBA28）或首个支持的 NVMe
512B namespace 提供。GPT 主/备份头、CRC、分区边界检查保留；未知卷不写入。
NVSTORE3 除元数据槽外允许写其数据区；NVSTORE1/2 仍仅允许写自身快照槽。

NVSTORE3 每个元数据槽默认 2 MiB，文件内容使用余下完整 4 KiB 磁盘块；
默认镜像逻辑大小 8 GiB。保存时只写元数据和提交头，按顺序 Flush；最终
提交结果不明确会冻结写入。恢复验证两份元数据和区间，再激活最新有效根。
数据块没有内容 CRC；没有验证所有实体盘断电语义。分区格式字段、旧盘兼容、
恢复顺序和当前边界见 [STORAGE-0.10.md](STORAGE-0.10.md)。

旧 NVSTORE1/2 仍用 NVSS0001 内联文件快照，按扇区流式导入/导出和 CRC 校验。
旧盘不会被自动转换；另存迁移工具创建新文件并保留源镜像。

## 安全与可靠性范围

本版可验证基本 Ring 3 隔离，但不承诺能承受任意敌对二进制、侧信道攻击或长期生产负载。缺少多用户权限、资源配额、信号、可靠 I/O 恢复以及生产级调度与内存压力处理。一个进程可以消耗共享文件节点或填满用户进程槽，触发返回错误；PID 1 负责管理。

长时间关闭中断的磁盘 I/O 会影响 PIT tick 计时精度。因此 `tempo` 和 `horizon` 的时间是处理到的 tick，不是经校准的墙上时钟。

## Folio 文档层

Folio 是一个运行在 Ring 3 的全屏用户态程序。内核提供独占屏幕租约、80×25 字符表面提交和带修饰键的 PS/2/串口键盘事件；程序退出或异常时内核恢复 Loom 的终端画面。表面提交一次校验完整用户缓冲区，不能写入 VGA 之外的地址。

编辑器在用户空间维护最多 32 KiB 的字符数组，每个字符带有粗体、斜体、下划线和段落属性。段落属性包含正文、两级标题、引用、四种对齐、项目符号、单/双倍行距和段前分页。布局器按 64 列、48 行正文页生成预览，RTF 写出时使用 11906×16838 twips 的页面、1 英寸边距、Courier New、标题字号和页脚页码。

`.nvd` 是 Nuvora 的小端格式：`NVFOLIO1`、字符数、CRC32 和每个字符的 3 字节记录。纯文本打开时将 CRLF 规范化为 LF；不接受控制字符或非 ASCII 字节。保存使用同目录临时文件和 `REPLACE` 系统调用，目标已打开时拒绝替换；失败时保留原文件。文档格式不写入普通 `.txt`/`.md`，避免把二进制元数据混入纯文本。
