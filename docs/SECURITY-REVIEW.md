本轮基线是 GitHub `main` 与本地一致的完整 `40f6970`。继续检查 ELF 加载、
用户页权限、设备等待与账户状态边界。本轮确认的是账户提交竞态和上一轮
输入隔离后的客户端恢复问题，未据此认定出现提权或新的密码读取漏洞。

| 问题 | 复现与影响 | 修复 |
| --- | --- | --- |
| 账户提交期间自动锁屏 | 最终 `store_sync` 等待允许定时器运行；锁屏清除 `account_job`，ADD/PASSWORD 已保存却返回 UID 0 | 提交前保存操作类型、目标 UID 和创建目录路径；候选数据库在可能的等待前准备完整，完成后保持锁定 |
| 窗口客户端把锁屏拒绝当成错误 | Music 主循环遇到 `-NV_EACCESS` 退出，Folio 反复处理输入错误；满客户端队列还会跳过 poll | 仅当公开账户状态确认锁屏时暂停输入与绘制，清空部分/满缓存，解锁后继续原窗口；其他权限错误照常返回 |
| 终端锁屏期间反复重试 | `read_line` 立即返回锁屏拒绝，Loom 重建提示符并继续读取，丢弃半行输入、无休眠循环 | 确认锁屏后休眠等待，保存已有输入；真正的权限及 I/O 错误继续返回 |

账户提交测试在实际账户服务的同步磁盘接口中触发真实 `account_tick`，
确认 ADD 和 PASSWORD 的目标 UID、持续锁定、秘密任务清除及重载后的
登录结果。原 UID 断言失败。共享窗口与行读取测试直接编译实际客户端，
原暂停/保留半行断言失败，修复后通过 UBSan 与额外 ASan/UBSan 检查。

锁屏仍立即撤销输入权限并清除请求秘密。已授权且进入磁盘提交的修改可

也未把所有 `EACCESS` 静默当作等待。公开账户状态查询失败时保留原错误。

执行记录见[账户与客户端验证](verification/0.15.0/security-session-summary.log)。

## 锁屏输入与显示权限（此前修复）

本轮以 GitHub `main` 与本地一致的完整 `50463ca` 为基线，继续检查
系统调用、账户撤权、文件访问和显示/窗口边界。确认并修复以下问题。

| 问题 | 影响与成立条件 | 修复 |
| --- | --- | --- |
| 窗口输入未重新检查锁定状态 | 应用可在锁屏后读取已排队的窗口事件；继承终端的子进程也能通过 stdin 消费旧按键 | `NV_WINDOW_POLL` 和路由 stdin 在读取/修改响应前检查交互权限；零长度读取同样拒绝 |
| 锁定切换时仍可转发输入 | 内核已锁定、桌面下一帧尚未切换登录页时，按键仍可进入旧聚焦窗口，留下解锁后可读的输入 | 内核 `NV_WINDOW_SEND` 要求已解锁会话，禁止向应用转发锁屏期间的新输入 |
| 先前取得的独占显示权未撤销 | 恢复模式应用可在锁屏后继续读键盘/指针和绘制画面，并阻挡恢复登录输入 | 锁定立即撤销普通应用的屏幕所有权；原始键盘、指针、文本/像素提交和重复领取均检查当前权限；可信登录管理器保留显示权 |
| 清屏缺少交互权限检查 | 后台应用可在锁屏时清除终端；恢复模式无人独占屏幕时可擦除登录文字 | `NV_CTL_CLEAR` 在路由或清除控制台之前统一检查权限 |

自动锁定、手动锁定、已登录管理器退出及注销都清除旧键盘/指针和窗口输入。
重复锁定不会再次清除新输入。窗口帧及待处理关闭、尺寸调整、焦点状态
保留，解锁后继续处理；普通应用需在解锁后重新领取被撤销的独占显示权。
后台计算、普通文件操作和私有窗口 stdout/画面更新仍可继续，登录界面
不会把它们显示为当前工作区。锁屏不是暂停全部进程或磁盘加密。

## 复现与验证

宿主回归直接包含实际内核代码，替换硬件 I/O 和受控账户/内存边界。
基线窗口 stdin/poll、原始按键/指针、文本/像素提交以及账户锁定撤权
断言均失败；基线清屏系统调用分支逐字提取到夹具后也未拒绝锁定操作，
输入转发检查在增加保护前失败。修复后检查权限错误
不改响应、队列或帧缓冲，真实帧缓冲带前后哨兵。新增 `console_security`
组，窗口及控制台夹具另外用 ASan/UBSan 运行。

生产 UEFI 启动中的 Ring 3 父进程建立自己的终端窗口，子进程继承它。
在真实的一分钟自动锁屏期间，父进程检查窗口 poll、stdin、零长度
stdin 和清屏拒绝，子进程分别检查两种 stdin 与清屏；错误密码仍不解锁。
正确密码解锁后检查输入和清屏恢复，并提交结果到私有数据盘。
这不使用诊断内核认证绕过。执行摘要见
[锁屏安全验证记录](verification/0.15.0/security-input-summary.log)；
准确测试范围及历史结果见 [TESTING](TESTING.md)。

文件规范路径与已打开描述符的权限重查在本轮继续审查，已有回归仍然
覆盖盘符、相对路径和 `..`。本轮未确认新的文件权限漏洞。
剩余的应用沙箱、资源配额、网络认证、离线磁盘和固件边界见下文。

## 网络归属与报文校验（上一轮）

上一轮审查以 GitHub `main` 与本地一致的完整 `cd10516` 为基线。
检查系统调用用户指针、ELF/页权限、账户与规范文件路径、窗口所有者及
网络输入；下表是已经用原实现复现、在该轮修改中修复的问题。

| 问题 | 影响与成立条件 | 修复 |
| --- | --- | --- |
| UDP 缓存没有进程归属 | 一个应用可读取另一应用的报文；进程退出或注销没有清除 UDP 数据，后续会话可读到旧数据；恢复控制台与桌面还会在注销后保留 PID | SEND/RECV 先领取端口，接收包绑定 PID；其他进程不能领取同一端口或通过通配读取；退出、exec、停止和会话结束清除归属及未读数据，注销主动清除管理进程与 PID 1 的网络状态，包括恢复控制台向桌面交接后 |
| 网络标识可预测 | TCP 初始序列号/端口、DHCP 事务 ID、DNS ID/端口由时钟等公开值计算，降低伪造匹配响应的难度 | 使用 RDSEED/RDRAND 随机源；无可用熵返回错误，不回退到时钟；TCP 重传保持原序列号，DHCP 熵失败保留旧配置 |
| DNS 只核对 ID | 匹配 ID 的响应即使问题名称或答案归属不同，也可能被当成所查域名的地址 | 校验响应标志、唯一 A/IN 问题、大小写无关名称及答案归属；只跟随该名称的有界 CNAME 链；检查压缩指针、标签和 RDATA 边界 |
| DHCP 接受外来 NAK | 匹配事务 ID 的非选定服务器拒绝报文可打断当前地址请求 | NAK 和 ACK 均核对选定服务器标识；缺失或不同标识不改变请求状态 |

UDP、DNS 和保留 PID 的账户注销原实现的攻击断言失败；原 DHCP 在外来 NAK 后重新发送发现
报文；原 TCP 开启未调用随机源。测试用保留地址和构造报文，不向公网
发送攻击数据。回归直接运行实际内核/客户端代码，硬件与系统调用入口
在宿主夹具中受控替换。

### 上轮接口变化

- `NV_SUB_CPU / NV_CPU_RANDOM` 使用 `struct nv_random`，返回 1–64 字节。
  内核先检查完整可写响应，未用尾部清零；部分熵失败清除全部数据，
  返回 `-NV_ENODEV`。零或超长请求不调用随机源；旧操作号和 ABI 保留。
- UDP 每个进程拥有一个当前接收端口。同一进程更换端口释放旧端口和
  旧缓存；冲突返回 `-NV_EBUSY`。RECV 的 `local_port=0` 只轮询自己
  已领取的端口，不能监听其他进程；应在等待报文前调用非零端口 RECV，
  或用 SEND 领取源端口。RECV 也检查当前网卡编号。端口表最多容纳
  `NV_TASK_MAX` 个所有者。
- 系统仍只有一个 UDP 待收包和一个活动 TCP 连接；此轮补上数据归属，
  没有实现每进程收件队列、公平调度或网络配额。
- DHCP、TCP 和域名解析依赖可用硬件熵；不支持 RDSEED/RDRAND 的机器
  或熵持续失败时会返回错误。该限制是显式失败，不能以可预测值替代。

### 上轮验证

`make test-host` 包含端口争用、通配读取、进程释放、旧端口复用、端口表
耗尽、注销时管理进程与 PID 1 的网络清理（包括管理权交接）、熵失败无副作用、稳定重传、外来 DHCP ACK/NAK、DNS 不匹配响应
和 CNAME 两种顺序。随机字节 ABI 检查全部长度、非法/只读/截断响应、
未用尾部和部分熵失败清除。

DNS 夹具逐一截断正常报文，检查自指/前向压缩指针与字面点标签，运行
10,000 份带保护页的畸形输入；网络夹具运行 12,000 份带保护页的
Ethernet/IPv4/DHCP 输入。另用 ASan/UBSan 运行这些客户端和内核夹具。

原生诊断增加随机字节系统调用断言。PC 网络测试在 e1000、e1000e 和
USB Ethernet 上使用真实 Ring 3 父子进程检查 UDP 所有权，并用本地 DNS
服务器先发送指向错误地址的不匹配问题/答案，再发送正确响应；随后
验证 HTTP 下载文件的完整字节。测试只使用私有镜像和容器内服务器。
最终结果见 [TESTING](TESTING.md) 与
[审查验证记录](verification/0.15.0/security-network-summary.log)。

## 仍然存在的安全边界

这次审查不代表系统已无安全问题。当前没有每应用权限沙箱、ASLR、
栈保护、资源配额或多连接隔离；同一账户启动的程序有该账户的数据权限。
单包 UDP 收件队列也可能被流量占用，尚无服务可用性保证。

网络没有 TLS 或 DNSSEC，ARP/DHCP/DNS 本身没有认证；能观察、修改链路
报文的攻击者仍可伪造响应。随机标识和内容匹配降低盲目伪造的机会，
不能替代链路和服务器认证。数据盘没有加密，启动镜像没有 Secure Boot
验证链，尚无 IOMMU/SMAP。离线磁盘、恶意 DMA、固件和实体机驱动边界
不属于本轮已验证结果；详见 [桌面安全边界](DESKTOP-SECURITY.md)。
